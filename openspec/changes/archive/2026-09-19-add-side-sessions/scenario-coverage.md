# Scenario coverage — add-side-sessions

Server scenarios run over a real server and real WebSockets, on the embedded runtime with a test provider
(`server/test/fixtures/side-sessions-provider.mjs`) that answers `ok: <prompt>`, holds a turn open on `HOLD` until
the test releases it, and calls the real `write` tool on `WRITE <name>` — so each conversation has a real session file
and each answer can be traced to its conversation. The attention scenario uses the scripted RPC agent, which is what
can block a turn on a dialog. Interface scenarios render components in jsdom; the start/switch/close path is also
driven end to end in `e2e/side-sessions.spec.ts`.
