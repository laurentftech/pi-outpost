# Scenario coverage — carry-referenced-figures-into-word

Every `#### Scenario:` this change's delta declares, matched to the assertion that would fail if the
contract broke. Ten scenarios, all in `docx-export`: six added with
`ReferencedImagesTravelAsPictures`, four carried by the modified `ExportDisplayedDocumentAsWord`.

Enumerated with `rg '^#### Scenario:' openspec/changes/carry-referenced-figures-into-word/specs/`.

Where the picture itself has to be *produced*, the evidence is in a real browser rather than in
jsdom, and deliberately so: jsdom has no 2D canvas context, so a referenced vector cannot be
rasterised there any more than a mermaid diagram can. A mock would be kinder than reality, which is
how this ships with every figure blank. The raster half, the resolution rule and every degradation
are real in jsdom and are asserted there.

All ten scenarios are now `covered`. `AReferencedVectorIsVectorInWord` required direct reader
observation: `word-verification.md` in this change confirms both Word Online and OnlyOffice drew the
SVG, not the PNG fallback — the scenario is now fully settled.

## `docx-export`

| Scenario | Coverage | Assertion evidence |
| --- | --- | --- |
| AFigureBesideTheDocumentIsCarried | covered | `e2e/docx-export-app.spec.ts` — "carries the figures the document references, wherever they sit on disk": opens the seeded report under the workspace's docs directory in the running app, captures the download, and asserts three `.svg` picture parts with three `.png` fallbacks and that none of the three alt texts appears as text. `e2e/docx-export.spec.ts` — "a referenced figure is carried as a vector, with a raster behind it" asserts the same for a figure beside the document and reads the alt text's absence from `word/document.xml`. In jsdom, `ui/src/export/referencedImages.test.ts` — "shows the picture instead of the words that stood in for it". |
| AFigureInAnotherDirectoryIsCarried | covered | `e2e/docx-export.spec.ts` — "a figure beside the document, below it, and above it all resolve": asserts the three paths actually requested are `docs/guide/beside.svg`, `docs/guide/figures/below.svg` and `docs/shared/above.svg` for a document two directories down, and that three vectors are carried. Repeated against the server's own `/files/raw` in `e2e/docx-export-app.spec.ts` (the seeded fixture references a figure beside, below and above the document). `ui/src/export/referencedImages.test.ts` — "resolves each reference against the document's own directory" pins the same three shapes by the pixel size of the part each one produced. |
| AReferencedVectorIsVectorInWord | covered | The package half is asserted: `e2e/docx-export.spec.ts` — "a referenced figure is carried as a vector, with a raster behind it" asserts exactly one `.svg` part, one `.png` part, an `svgBlip` extension on the picture, and that the vector in the package is the workspace figure itself. The picture is built by the same `vectorRun` a rendered diagram is built by, and real Word reported that construct as `SHAPE-TYPE: 17` (`wdInlineShapeScalableVectorGraphic`) in `openspec/changes/archive/2026-09-06-add-docx-export/word-verification.md`. Direct observation: `word-verification.md` in this change confirms Word Online and OnlyOffice both drew the SVG (crisp at high zoom), not the PNG fallback. |
| WhatTheViewerShowsIsWhatTheExportCarries | covered | `ui/src/export/loadReferencedImage.test.ts` — "builds the URL the viewer builds for the same document and reference": asserts the export's URL equals `rawFileUrl(serverUrl, resolveRelativeHref(path, src), token)` — the two helpers the viewer's `img` calls — *and* equals the literal string, so neither side of the comparison can move quietly. "resolves against the document's own directory, up as well as down" pins the three relative shapes. End to end, `e2e/docx-export-app.spec.ts` — "carries the figures the document references" exports the very document the viewer is displaying and finds those figures in it. |
| AMissingReferenceFallsBackToItsText | covered | `ui/src/export/referencedImages.test.ts` — "falls back to the alt text for …, and carries the rest of the document", run over a file that is not there, a path the server refuses (403), a payload that is not an image, and a server that cannot be reached: each asserts the alt text, the surrounding text and heading, and that no `<w:drawing>` was emitted. "leaves a package with no relationship pointing at a part it does not contain" runs the `packageFaults` validator over an export whose three references all failed and asserts no faults and no media parts. In the running app, `e2e/docx-export-app.spec.ts` — "falls back to the words when a referenced figure has gone from disk" removes a figure underneath the application and asserts the other two still travel while the third is its alt text. |
| AnAbsoluteUrlIsNotFetched | covered | `e2e/docx-export.spec.ts` — "an absolute URL is not fetched, however plausible it looks": records every request the page makes and asserts none mentions `example.com`, that no media part was produced, and that the alt text is in the document. `ui/src/export/referencedImages.test.ts` — "does not reach off the origin for an absolute reference, and keeps its words" asserts `fetch` was never called for an `https:` or a `data:` reference. `ui/src/export/loadReferencedImage.test.ts` — "refuses anything that would reach off the origin" and "never asks for a reference that points off the origin" pin the rule at the URL, before any request exists. |
| DownloadMarkdownAsWord | covered | `e2e/docx-export-app.spec.ts` — "exports the open file, and hands over a .docx named after it": drives the real button, captures the download, asserts the bytes begin `PK` and unzip to a package holding `word/document.xml`. Pre-existing; unchanged by this delta. |
| ExportNamesTheFileAfterItsSource | covered | `ui/src/export/docxExport.test.ts` — "replaces the source's extension rather than appending to it", "keeps the dots that are part of the name", "gives a name with no extension one", "treats a dotfile's leading dot as its name". | NotOfferedForUnexportableViews | covered | `ui/src/components/FileViewer.docxExport.test.tsx` — "does not offer it for an image", "does not offer it for a PDF", "does not offer it for a file that failed to load", "does not offer it while the uncommitted diff is showing". Pre-existing. |
| ExportIsOffline | covered | `e2e/docx-export.spec.ts` — "exporting stays on the origin that served the application": exports a document that *does* reference a figure, asserts a `/files/raw` request was made and the figure arrived (so the test is not vacuous), and that no request left the harness origin. The amended requirement's other half — that an absolute URL is not reached for — is `AnAbsoluteUrlIsNotFetched` above. |
