# Scenario coverage

Scenarios were listed with `rg '^#### Scenario:' openspec/changes/btw-side-question/`. The wire tests
run the real server and a real session, embedded and with a real Pi RPC child, against a fake
provider (`server/test/fixtures/btw-provider.mjs`) that records every request it receives. The
provider holds a turn open after a real `read`, so the side question is asked in the middle of the
turn. Every check below was also done by hand in the running app (standalone UI on a live
embedded server): a question asked mid-turn, a slow one replaced, `/btw` alone, a provider failure,
the turn ending with a question still pending, and **+ new** closing the panel.

After the gate is released, the turn ends with its `done` kept in the next request, and no turn request contains the question or the answer. `rpc: a real Pi child answers /btw mid-turn…` checks the same through the RPC child. |
