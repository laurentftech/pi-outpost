# Scenario coverage — add-structured-exchange-project-setup

Every scenario the four specs declare, and the assertion that would fail if its contract broke.

The boundaries: the profile format, the end check, rules validation and both view generators are pure code in
`shared`, tested under Node on the smallest file or document that breaks each rule, asserting rule and pointer or
the exact labels and cells. The agent's tools are driven as the agent calls them against real projects on disk,
asserting the text it reads back and whether anything reached the interface's channel. The reader's statement and
a generated rule-pattern result are rendered in jsdom. The reference validator is the shipped bundle, rebuilt and
copied to a directory with no path back to the repository. The skills are loaded by the SDK's real loader.

Scenarios carried unchanged into a MODIFIED requirement keep the evidence of the change that introduced them;
each cited test title was checked to still exist in the cited file, and the suites were run.

Also driven in the running widget (the embed bench, "bench profiles"): the rules register and the rule patterns
presented by the real tool, the refusal of a requirement verifying a requirement, and the patterns mocked up first
and approved before the generator was written.
