# Scenario coverage

Scenarios enumerated with:

```sh
rg '^#### Scenario:' openspec/changes/add-integrated-terminal/specs/
```

Every citation below names a test whose assertions fail if the scenario's contract
breaks. Where a scenario is proved on the wire — a real server, a real socket — that
is the citation given, because the UI hiding a control is not the same claim as the
server refusing the message.

| Spec scenario | State | Test and contract assertion |
|---|---|---|

| `terminal / Multi-tab management and inline renaming` | covered | `ui/src/components/TerminalPanel.test.tsx` — “adds a new tab when clicking + button”, “allows renaming tabs on double click”, “handles tab renaming with Escape key and empty string”, “handles clicking tabs to switch active tab” (asserts the active class moves), “handles tab closing and active tab switching”, “does not render a close button when only one tab exists”. `e2e/terminal.spec.ts` — “supports adding and renaming terminal tabs”. |
| `terminal / PWD synchronization to workspace root` | covered | `ui/src/components/TerminalPanel.test.tsx` — “calls onSetWorkspaceRoot when clicking open as project button”, “handles root filesystem confirmation prompt when syncing” (asserts `/` is confirmed before it is opened), “handles terminal subscriptions: onData, onCwd, OSC 7, onExit, onError” (asserts the OSC 7 path updates the directory shown), “routes typed keystrokes to sendTerminalInput and throttles cwd requests on Enter” (asserts the throttle window and its catch-up timer). `ui/src/App.test.tsx` — “toggles terminal panel and repoints workspace root”, “updates sandbox config when embedded or openProject unset”, “updates sandbox config on unconstrained server” cover the three repointing branches and assert the existing sandbox flags survive. |
| `config / Default configuration disables terminal` | covered | `server/test/terminalWire.test.mjs` — “a server with no terminal configured advertises none and refuses to open one” asserts the snapshot carries `{ enabled: false }` **and** that a `terminal_open` sent anyway comes back as `terminal_error`, with no output reaching the socket afterwards. `e2e/terminal.spec.ts` — “hides terminal button and disarms shortcut on default server”. |
| `config / Command-line flag and environment variable override` | covered | `server/test/cli.test.ts` — “the flag decides, and its absence leaves the decision to configuration” (`--terminal` → `true`, `--no-terminal` → `false`, absent → `undefined` so the file still decides) and “the two flags contradict each other rather than one quietly winning”. `server/test/terminalWire.test.mjs` — “the environment variable turns the terminal on where no config file asked for it” and “PI_OUTPOST_TERMINAL=0 leaves it off, so the variable is a switch and not a mere presence” assert both directions of the variable at the wire. |
| `config / Sandbox lock prevents terminal tampering` | covered | `server/test/terminalWire.test.mjs` — “a locked terminal says so in the snapshot, so Settings cannot offer to switch it on” asserts `locked: true` reaches the client, and “a locked terminal cannot be switched on from the client, because no wire path exists” sends the `update_config` anyway and asserts the terminal stays off and `terminal_open` is still refused. |
| `model / Opening a terminal` | covered | `server/test/terminalManager.test.ts` — “open, write, resize, and close terminal lifecycle” asserts a PTY spawns, output reaches the data callback, resize succeeds and a write after close returns `false`. `ui/src/useAgent.test.ts` — “sends terminal wire messages and notifies listeners” asserts every outbound message (`terminal_open`, `terminal_input`, `terminal_get_cwd`, `terminal_resize`, `terminal_close`) and every inbound one (`terminal_data`, `terminal_cwd`, `terminal_exit`, `terminal_error`) reaches its listener with the right value. |
| `model / Server rejects terminal when disabled` | covered | `server/test/terminalWire.test.mjs` — “a server with no terminal configured advertises none and refuses to open one” asserts the exact refusal message, and that input sent after it produces no `terminal_data` for two seconds; “the sandbox refuses the terminal on its own, even when the feature is enabled” asserts the second, independent gate (`sandbox.allowBash: false`). |
| `model / Cross-socket access is refused` | covered | `server/test/terminalManager.test.ts` — “isolates terminals strictly per socket” asserts a third socket can neither write to nor close another socket's terminal id, and that `closeAllForSocket` leaves the other socket's session alive; “concurrent same-tick opens serialize cleanly without leaking orphan processes” asserts the surviving session is reachable after two opens in one tick. |
| `model / Session snapshot reports terminal settings` | covered | `server/test/terminalWire.test.mjs` — “a server with no terminal configured advertises none and refuses to open one” asserts the snapshot's `terminal` object exactly (`{ enabled: false }`, no stray keys), and “a locked terminal says so in the snapshot…” asserts `{ enabled: true, locked: true }`. `ui/src/App.test.tsx` — “toggles terminal panel and repoints workspace root” asserts the UI reads that field rather than assuming the feature is present. |

## Not covered here, deliberately

- **Windows shell resolution** (`findWindowsGitBash`, the PowerShell and `cmd` fallbacks) runs only on `win32`. `server/test/terminalManager.test.ts` asserts the non-Windows answer, and on Windows asserts the resolved shell is one of Git Bash, PowerShell or `cmd`. Which of the three a given host resolves to is not asserted, because it depends on what is installed there.
- **A working PTY.** `node-pty` is an optional dependency: where it is missing the server answers `terminal_error` and the rest of the product still runs. The wire tests assert the *configuration* gates, and never require a shell to spawn.
