# Design

## Context

`mxc-linux-bubblewrap` made `"mxc"` resolve per platform (`mxcExecutorName`: `wxc-exec.exe` on Windows,
`lxc-exec` on Linux, none elsewhere) and added `mxcLinuxConfig`, `checkLinuxMxcRunner`, `isLinuxMxc` and
a Linux branch in `confinedBash.ts`, `index.ts` (`terminalConfinement`) and `terminalManager.ts`
(`shellUnder`). On macOS today `"mxc"` is refused ("MXC has no executor for darwin") and the terminal's
`getCwd` asks `lsof` for the cwd of the pty's own pid, which under a runner is the executor's.

`mxc-exec-mac` takes the same request document as `lxc-exec`, with `containment: "seatbelt"`; Seatbelt
is a deny-by-default profile generated from `filesystem` and `network`. It ships in `bin/arm64` only.
The developer's Mac is Intel, so the real executor runs on an Apple-silicon Mac reached over ssh and on
GitHub's `macos-latest` runner (Apple silicon).

## Goals / Non-Goals

**Goals:**
- The agent's `bash` and the terminal confined on Apple-silicon macOS by `"mxc"`, with the limits of
  every other runner, `sandbox.allowedHosts` included.
- git usable and quiet inside the sandbox.
- Real-executor tests, run in CI on `macos-latest`.

**Non-Goals:**
- Intel Macs: no executor exists; refused with the reason.
- The standalone executable (`build-exe`) carrying `mxc-exec-mac`: the npm install has it; a macOS
  SEA build can follow if anyone ships one.
- `sandbox.bashImage` (WSLC) on macOS: refused, as on Linux.
- Using the SDK's in-process API (`spawnWithPty` through `libmxc_ffi.dylib`): pi-outpost spawns the
  executor like on the other platforms, which the pty probe showed works.

## Decisions

**One request builder per backend, not a shared one.** `mxcMacConfig` beside `mxcLinuxConfig`: the
same inputs, `containment: "seatbelt"`, macOS system trees (`/usr`, `/bin`, `/sbin`, `/System`,
`/Library`, `/private/etc`, `/private/var/db/xcode_select_link`, `/opt/homebrew` when present), the
developer directory (`xcode-select -p`, read once). Sharing one builder with a backend switch would mix
two lists of system paths that have nothing in common. Paths are resolved (`/tmp` → `/private/tmp`,
`/var/folders` → `/private/var/folders`) before they go in: Seatbelt matches the real path.

**git without the `xcrun` shim.** `/usr/bin/git` is a shim that asks `confstr` for a per-user temp and
cache directory (refused under Seatbelt), falls back to `/tmp` (not writable), warns on every call and
leaves a `Library/` cache in `HOME`. The confined search path puts the real git's folder first —
`<developer dir>/usr/bin` for Command Line Tools, `<developer dir>/Toolchains/XcodeDefault.xctoolchain/usr/bin`
or `<developer dir>/usr/bin` for Xcode, whichever holds `git` — so the shim is never reached. Alternatives:
making `/private/tmp` writable (shared with every user, rejected); `HOME` in the private temp (hides
`Library/` but keeps the warnings). To be confirmed by the first real run; the fallback is a
`DEVELOPER_DIR` plus `TMPDIR`-only approach if the real binaries also call `confstr`.

**Network: the proxy shape of Linux.** `egress: deny`, `ingress: deny`, `runtimeConfig.networkProxy`
(measured: the listed host relayed, nothing else reachable, the loopback included). `ingress: allow` is
accepted by Seatbelt but not needed.

**Self-check:** one confined `/usr/bin/true` with `egress: allow`, MXC's `{"error":{"message"}}` passed
on as the reason — the Linux check with another command and backend. Refused off macOS for an
`mxc-exec-mac` path, as `lxc-exec` is off Linux.

**The terminal's working directory.** `shellUnder` (Linux, `/proc`) gets a macOS twin reading the
process tree from `ps -A -o pid=,ppid=,comm=` (the server's `ps`, unconfined) and `lsof` for the shell's
cwd. Which processes sit between the executor and the shell is measured in the first real run.

**Config:** `bashImage` refused with `mxc-exec-mac` (WSLC is Windows only); `"mxc"` on an Intel Mac
refused naming the architecture (`bundledMxcExecutor` already returns none for x64 on darwin; the
message says which).

## Risks / Trade-offs

- [The developer cannot run the executor locally] → probes over ssh on an Apple-silicon Mac, and a CI
  job on `macos-latest` running the real-executor tests on every pull request.
- [Seatbelt's profile is generated by MXC; a path pi-outpost denies may be readable through another
  rule] → the real tests read the denied paths and check the host, as on Linux.
- [macOS updates change Seatbelt or the developer tools' layout] → the CI job runs on GitHub's current
  macOS image and fails loudly.
- [Homebrew tools outside `/opt/homebrew` or the search path] → read-only access follows the search
  path's installations, as on Linux (`toolTrees`).
