# Scenario coverage

Inventory: `rg '^#### Scenario:' openspec/changes/workspace-code-search/` lists ten scenarios, all of them below. The surface was found with OpenLore's prompt-time briefing and `rg` over `server/src/fileBrowser.ts`, `server/src/pdf.ts`, `server/src/index.ts`, `ui/src/useAgent.ts`, `ui/src/components/FileViewer.tsx` and `PdfViewer.tsx`. The server tests walk real directories and real PDF fixtures (`server/test/fixtures/pdf-*.pdf`). The wire test runs a real server, and the e2e tests drive the built app in Chromium against a real server.

| Applicable scenario | Status | Tests and assertions |
|---|---|---|
| SearchAcrossWorkspaceFiles | covered | `server/test/contentSearch.test.ts` "SearchAcrossWorkspaceFiles: …" asserts the exact `[path, line, column]` of every text hit, including a CRLF file, and that each excerpt holds the match. `server/test/contentSearchWire.test.mjs` "answers the files under its root …" asserts the same over the socket. `ui/src/components/Sidebar.test.tsx` "SearchAcrossWorkspaceFiles: …" asserts the grouping, line number and marked match. `e2e/content-search.spec.ts` "SearchAcrossWorkspaceFiles and OpenMatchingLine" asserts the count, the file and the marked excerpt in the running app. |
| SearchPdfPagesAcrossTheWholeDocument | covered | `server/test/contentSearch.test.ts` "SearchPdfPagesAcrossTheWholeDocument: …" asserts with `deepEqual` the hit `{ path, kind: "pdf-page", page: 2, excerpt }` for text on page 2 only. `server/test/pdf.test.ts` "gives each page's text, in page order" asserts the page attribution. The e2e test of the same name asserts the "p. 2" row and its marked excerpt. |
| EmptyContentSearch | covered | `server/test/contentSearch.test.ts` "EmptyContentSearch: …" asserts no hits for `""`, `"   "` and `"\t\n"`. `ui/src/useAgent.test.ts` "EmptyContentSearch: …" asserts that no frame is sent and the state stays null. `Sidebar.test.tsx` "EmptyContentSearch: …" asserts that no results and no "No matches" are shown. The e2e "NoContentMatches and EmptyContentSearch" asserts that no `search_content` frame leaves the browser for a whitespace query and no status is shown. |
| NoContentMatches | covered | `server/test/contentSearch.test.ts` "NoContentMatches: …" asserts empty hits, not truncated. `Sidebar.test.tsx` "NoContentMatches: …" and the e2e test assert "No matches" in the Files panel. |
| SearchSkipsIgnoredDirectoriesAndBinaryFiles | covered | `server/test/contentSearch.test.ts` "SearchSkipsIgnoredDirectoriesAndBinaryFiles: …" puts the query in `node_modules`, `dist`, a dot directory and a NUL-bearing file, then asserts no hit for them and that the set of paths answering is exactly the three text files. The e2e test asserts that the `node_modules` match is not listed. |
| ScannedPdfPageHasNoTextMatches | covered | `server/test/contentSearch.test.ts` "ScannedPdfPageHasNoTextMatches: …" asserts that `pdf-mixed-scan.pdf` answers only for its text page and that `skipped` counts only the corrupt PDF, not the scanned page. `server/test/pdf.test.ts` "a page with no text layer gives an empty string, not an error" asserts `""` for the image-only page. |
| SearchDoesNotFollowLinksOutsideRoot | covered | `server/test/contentSearch.test.ts` "SearchDoesNotFollowLinksOutsideRoot: …" links a matching file and a directory outside the root, then asserts no hit (skipped where the platform cannot create symlinks, as `fileBrowser.test.ts` does). `server/test/contentSearchWire.test.mjs` asserts that no excerpt from the outside file reaches the socket. |
| OpenMatchingLine | covered | `ui/src/components/FileViewer.find.test.tsx` "OpenMatchingLine: …" asserts that a Markdown file switches to source, find holds the query at "2/2", and the selection is `{ from: 19, to: 25 }` on line 3, not the first match. "lands on the hit's line in a CRLF file too" asserts the same through CRLF, and "a refresh of the file does not jump back to the hit" covers the single use. In the running app, the e2e test asserts that the current match is on line 10 of the editor (not line 2) and in the viewport. That test found a real defect: on the first file opened, CodeMirror loads lazily and the selection landed on no editor. `CodeEditor`'s `onReady` fixes it. |
| OpenMatchingPdfPage | covered | `ui/src/components/PdfViewer.test.tsx` "OpenMatchingPdfPage: …" asserts on a five-page document that the viewer goes to page 5, reports `currentIndex: 1` of 2 once indexing is done, never settles on the cover's match, and marks the match in page 5's text layer. "falls back to the next match …" covers a stale page. `FileViewer.find.test.tsx` "OpenMatchingPdfPage: …" asserts that the PdfViewer receives `findQuery` and `startAt: { page: 3 }`. In the running app, the e2e test asserts that `mark.find-match-current` sits in page 2's text layer and in the viewport. |
| WorkspaceChangesDuringSearch | covered | `ui/src/useAgent.test.ts` "WorkspaceChangesDuringSearch: …" asserts that the state is null after `workspace_switched` and that the late answer does not repopulate it. `server/test/contentSearchWire.test.mjs` "a search superseded by a newer one is never answered" asserts the server-side abort (it fails with the abort removed). In the running app, the e2e test holds the server's answer, switches project, releases it behind a FIFO checkpoint, then asserts that no hit for the old project is shown, either in the panel or after reopening it. |
