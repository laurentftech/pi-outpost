# Scenario coverage

Inventory: `rg '^#### Scenario:' openspec/changes/on-demand-tools-stay-withheld/` lists three scenarios; all three are below. OpenLore's `orient` was not available (`npx` would not install it without a prompt), so the surface was found with `rg` over `server/src/index.ts`, `server/src/embeddedRuntime.ts` and the SDK's `AgentSession.navigateTree`. Every test below runs a real server and a real embedded session, and asserts the tool list the provider was sent (`server/test/fixtures/document-tools-provider.mjs`), not the server's own account of it. The on-demand set is imported from production (`DOCUMENT_TOOLS`, `PROJECT_MODEL_TOOL`, `WORK_PLAN_EXTENDED_TOOL`), not listed by hand.

| Applicable scenario | Status | Tests and assertions |
|---|---|---|
| Going back in the conversation publishes nothing | covered | `server/test/documentToolsWire.test.mjs` "going back in the conversation publishes no withheld tool" asserts with `deepEqual` that the request after an `edit_prompt` and the request after a `navigate_tree` followed by a prompt carry exactly the first turn's tools. Without the fix, the first of them carries all seventeen on-demand tools. Running app: editing the first prompt through the UI's "Edit this prompt" control sends no on-demand tool; the same walk without the fix sends seventeen. |
| A rewind keeps the tools in use | covered | `server/test/documentToolsWire.test.mjs` "a tool in use keeps its place across a rewind" asserts `docx_extract`, called in the first turn, is still sent after the quiet turn's message is edited, and that `pdf_extract`, `xlsx_extract`, `pptx_extract` and `mail_extract` are not. Without the fix, the four are sent. |
| A tool switched on behind the server's back is withdrawn | covered | `server/test/documentToolsWire.test.mjs` "a tool published behind the server's back is withdrawn before the next turn" runs an extension command (`server/test/fixtures/activate-all-tools-command.mjs`) that switches every registered tool on, then asserts the next turn's request carries no on-demand tool. With the pre-prompt reassertion removed, the test fails. |

Running app: `web` rebuilt, the server started through the test harness with the recording provider, and Chromium driven with Playwright: two prompts, an edit of the first through the UI, then a monkey pass (a second edit immediately followed by a prompt and a double Enter). Each request's on-demand tools were read from the provider's log: none on any of the five requests, no page errors. The same walk without the fix: all seventeen on every request from the edit onward.

The end-of-turn reassertion has no test of its own. The pre-prompt one covers every path that starts a turn from a prompt, and the end-of-turn one is defence for turns started otherwise.
