# Scenario coverage — read-the-comments-in-a-pdf

Capability: `pdf-documents` (4 requirements, 13 scenarios).

The fixtures are `server/test/fixtures/pdf-comments.pdf` (a reviewed contract whose review is all
annotations), `pdf-comments-bare.pdf` (the same pages without them) and `pdf-comments-many.pdf`
(60 notes on one page), built by `commentsDoc`, `commentsBareDoc` and `manyCommentsDoc` in
`server/test/fixtures/make-pdfs.mjs`. Every integration test below runs the real `extractPdf` over
pdf.js 6.2.108; none stubs the annotation reader except where named.

## pdf-documents

| Scenario | Coverage | Evidence |
| --- | --- | --- |
| ANoteIsReturnedWithItsPage | covered | `server/test/pdfComments.test.ts` — "ANoteIsReturnedWithItsPage: page 2's note, with its author, date and remark, and on no other page". Asserts page 2's section ends with `### Comments on page 2` followed by `- **Note** — Paul Martin, 2026-09-14:` and `> Missing the annex reference.`, and that page 1's section does not contain the remark. Also asserts the text box's words appear exactly once in the whole extraction. `server/test/pdfCommentsWire.test.mjs` asserts the same entries reach the model through a real server and session. |
| RepliesAndStatesFollowTheirComment | covered | `server/test/pdfComments.test.ts` — "RepliesAndStatesFollowTheirComment: the reply and the Accepted state sit under the highlight, not beside it". Asserts the exact five lines: the highlight, its remark, the indented `- **Reply** — Paul Martin, 2026-09-13:` with its quoted remark, and `  - State: **Accepted** — Paul Martin, 2026-09-14`; that page 1 has exactly five top-level entries (so neither the reply nor the state is one); that the state's own remark is not shown; and that page 2's reply to a page-1 comment is listed as `(to a comment not on this page)`. "an orphan state, a reply loop and an empty reply are neither lost nor invented" covers the loop and orphan-state paths on `commentsOf` directly. |
| SuggestionsAreNamed | covered | `server/test/pdfComments.test.ts` — "SuggestionsAreNamed: a strike-out and a caret without a remark are the reviewer's suggestions". Asserts the whole lines `- **Suggested deletion** — Marie Dupont, 2026-09-12, on "in any event"` and `- **Suggested insertion** — Marie Dupont, 2026-09-12, before "lists"`, anchored at line end, so a remark or a wrong anchor fails it. |
| WhatIsNotACommentIsLeftOut | covered | `server/test/pdfComments.test.ts` — "WhatIsNotACommentIsLeftOut: no link, form field, popup, bare shape or grouped annotation is listed". Asserts no `example.com` (the link), `buyer_name` (the form field), `Shape` (the bare rectangle and the grouped square) or grouped remark; and that the highlight's remark, which pdf.js also reports on its popup, and the note's, which it reports on the grouped square, each appear exactly once. |
| ARemarkCannotPassForStructure | covered | `server/test/pdfComments.test.ts` — "ARemarkCannotPassForStructure: a remark reading like a page heading and a note stays quoted". Asserts the remark comes back as `  > ## Page 9` / `  > > Truncated` under Mallory's note, that no line starts with `## Page 9` or `> Truncated`, and that the page headings are exactly `1`, `2`. "control and bidi-override characters are removed; author names and anchors stay on one line" asserts an author name carrying `\n## Page 3` is folded into the entry's line, and that U+202E and BEL are removed from a remark. |
| TablesModeLeavesCommentsOut | covered | `server/test/pdfComments.test.ts` — "TablesModeLeavesCommentsOut: no block, but the notice counts them and says how to read them". In `tables` mode, asserts no `Comments on page` block and no remark, and a leading notice counting 9 comments and naming `mode "text"`. |
| AHighlightQuotesItsPassage | covered | `server/test/pdfComments.test.ts` — "AHighlightQuotesItsPassage: the three highlighted words, not the sentence around them". Asserts `on "the delivery date":` and that no anchor contains `supplier` or `June`, the words on either side. "textUnder: a partial word is widened to the whole word, and a region over no text quotes nothing" covers a box starting inside a word, a box over no text, and a box grazing a line. |
| AHighlightAcrossTwoLines | covered | `server/test/pdfComments.test.ts` — "AHighlightAcrossTwoLines: the end of one line and the start of the next, in reading order". Asserts the whole entry `- **Highlight** — Paul Martin, 2026-09-13, on "the contract value":` with its remark: the first line's end, then the second line's start. |
| AnchoringLeavesTheTextAlone | covered | `server/test/pdfComments.test.ts` — "AnchoringLeavesTheTextAlone: every page reads exactly as it does without its annotations". For modes `text` and `both`, asserts each page's section up to its comments block equals the same page extracted from `pdf-comments-bare.pdf`, character for character. |
| CommentsAreAnnounced | covered | `server/test/pdfComments.test.ts` — "CommentsAreAnnounced: the count leads, before the first page's content". Asserts the extraction starts with the notice counting 9 comments and naming where they are, that it precedes `## Page 1`, and that extracting page 2 alone counts 3. `server/test/pdfTool.test.ts` — "returns a reviewed document's comments with its pages, and writes them to a file too" asserts the same notice leads the tool's answer and the file `output_path` writes. |
| NoCommentsAnnounceNothing | covered | `server/test/pdfComments.test.ts` — "NoCommentsAnnounceNothing: a document without annotations has no notice and no block". For `pdf-comments-bare`, `pdf-text` and `pdf-strike`, asserts neither `review comment` nor `Comments on page` appears. |
| ManyCommentsAreCapped | covered | `server/test/pdfComments.test.ts` — "ManyCommentsAreCapped: 50 listed, and the other 10 counted". Asserts exactly 50 note entries, that the block ends with note 50 followed by `- _10 more comments on this page not listed._`, that note 51 is absent, and that the notice still counts 60. "a remark past the limit is cut, and says so" covers the 2 000-character remark cap. |
| UnreadableAnnotationsDoNotFailThePage | covered | `server/test/pdfComments.test.ts` — "UnreadableAnnotationsDoNotFailThePage: pdf.js failing to read them costs the comments, not the text". Replaces pdf.js's own `PDFPageProxy.prototype.getAnnotations` for one real extraction so the first page's read throws; asserts it was called twice, that page 1 still returns its text and says `_The comments on this page could not be read._`, and that page 2's comments are listed. "CommentReadingIsBounded: an annotation read that outruns the budget fails the call like any other read" asserts a read that never settles fails with the `budget` reason, while an ordinary failure returns `null`. |
