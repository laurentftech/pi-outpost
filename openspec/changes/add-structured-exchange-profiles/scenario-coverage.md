# Scenario coverage — add-structured-exchange-profiles

Every scenario the three deltas declare, and the assertion that would fail if its contract broke. A
scenario is `covered` only when a test's *assertions* check the WHEN/THEN at the boundary the scenario
describes.

Five boundaries carry this change, and each scenario is cited at the one it names. The formats and the
rules are pure code in `shared`, tested under Node on the smallest profile or document that breaks each
rule, asserting rule and pointer. The project's files are tested on real directories: what is outside
the project, what a link resolves to, what an edit changes on the next read. The agent's tools are
driven as the agent calls them, asserting the text it reads back, what reaches the interface's channel,
and whether a figure file exists afterwards. The reader's statement is tested over a real socket with a
scripted RPC child, live and on replay, and rendered in jsdom. The reference validator is the shipped
bundle, rebuilt and copied to a directory with no path back to the repository.

Every fixture document passes the core contract through the real parser first, so no profile test
passes on a document the core would have refused. Three rules were mutated to confirm the check tests
bite (closed enumeration reported instead of refused, added items exempted from required attributes,
sequences held): each failed the suite. Neutering both conformance announcements failed the wire test.
